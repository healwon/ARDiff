# same old, two news

다섯 개의 old마다 같은 동작인 new(`Eq`)와 다른 동작인 new(`NEq`)가 하나씩 있습니다. 같은 old에서 어떤 수정은 괜찮고 어떤 수정은 동작을 바꾸는지 나란히 볼 수 있습니다.
`Eq`는 식만 바꾼 것이 아니라 계산 방법 자체를 바꾼 버전이라, 같다는 것을 보이려면 코드를 따라가며 추론해야 합니다.

| old | `Eq` new | `NEq` new |
|---|---|---|
| `EvenSum` | 짝수를 하나씩 검사하는 대신 n 아래 짝수의 개수 `(n + 1) / 2`만큼 돌며 `2 * i`를 더함 | `i < n` → `i <= n` (n이 짝수면 n을 더함) |
| `Avg3` | 합을 6으로 나눈 몫과 나머지로 나눠 `s / 6 * 2 + (s - s / 6 * 6) / 3` (0 쪽으로 버림이 그대로 유지됨) | `a / 3 + b / 3 + c / 3` (나머지 손실) |
| `TaxQty` | `total * 1.1`을 한 번의 나눗셈으로: `tax`에 나머지를 두고 `(total * 11 - tax) / 10` | `tax = price / 10 * qty` (나머지 손실) |
| `AbsDiff` | 두 값을 먼저 크기순으로 `hi`, `lo`에 놓고 `hi - lo` | `d < 0` → `d < -1` (차이가 -1일 때 다름) |
| `Overtime` | 보너스 조건을 `pay / 10 > 40`으로 (`pay`는 항상 5로 끝나므로 `pay > 405`와 같음) | `pay > 405` → `pay >= 405` (40시간에서 다름) |

`Overtime`은 공통 코드를 추상화한 첫 질의에서 z3가 실제로는 나올 수 없는 `pay`/`base` 값을 고르기 때문에, ARDiff(-lite)가 여러 번 refinement를 거친 뒤에야 결론을 냅니다.

원래 ARDiff는 바뀐 문장의 구조가 달라지면(새 `if`/`else`, 루프 앞에 끼워 넣은 문장, 경로가 갈리는 `?:`) 변경 추출에서 실패하거나 경로별 변수를 잘못 비교합니다. 그래서 `Eq`는 old와 문장 구조는 같게 두고 식과 계산 방법만 바꿨습니다.
